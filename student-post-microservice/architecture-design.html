2. Authentication and request flow

1. Sign in
The UI redirects the browser to IAM. IAM authenticates the user and returns to /auth/callback using Authorization Code + PKCE.
2. Token
IAM issues a signed access token containing sub, username and roles claims.
3. Gateway
The UI sends Authorization: Bearer <access token>. The gateway validates issuer and signature, then maps each role to Spring authority ROLE_<role>.
4. Service
The gateway routes the original bearer token to the Topic or IAM service. Each service also validates it and makes its own authorization decision.

Important: UI buttons are convenience only. Ownership and role checks are enforced in the Topic Service; the gateway adds a second route-level role check.

4. Topic data and visibility

Ownership

On create, the Topic Service derives ownerUsername from the validated JWT rather than trusting a username sent by the UI.

Visibility

PUBLIC topics appear in the public list. PRIVATE topics can be viewed only by their owner or an admin.

Listing experience

List pages show a short preview. The full content is loaded only after the user opens that topic’s dedicated page.

Write operations

Updates change title, date, content and visibility only. Owner identity is not editable through the API.

6. Operational notes and known development constraints

  • Start Eureka and Config Server before Topic Service; start IAM before services that validate IAM tokens; then start the gateway and UI.
  • After IAM restarts, sign in again. The current IAM implementation generates its RSA/JWK signing key at startup, invalidating previously issued tokens and logout hints.
  • The UI proxy is for local Vite development. A deployed UI should set VITE_API_GATEWAY_URL and configure the gateway’s allowed origins for its real UI URL.
  • IAM uses MySQL database iam_db and seeds an admin account if absent. Change default credentials before exposing the application outside local development.
  • This is intentionally a learning-project design; add persistent signing keys, token revocation strategy, audit logging, validation, rate limits and production secret management before production use.
